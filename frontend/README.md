# DocumentAI Frontend

Web interface for the DocumentAI document processing pipeline. Upload Ercole pension fund PDFs, review the structured extraction results, and ask follow-up questions in natural language.

Built with **Next.js 14** · **TypeScript** · **Tailwind CSS** · **shadcn/ui**

---

## Prerequisites

- Node.js 18+
- npm 9+ (or pnpm / yarn)
- The backend API running on `http://localhost:8000` (see root README)

---

## Setup

```bash
# Install dependencies
npm install

# Copy environment config
cp .env.example .env.local
```

The default `.env.example` already points to `http://localhost:8000`. Edit `.env.local` to change the API URL.

---

## Running

```bash
# Development (hot reload)
npm run dev

# Production build
npm run build
npm run start

# Type check
npm run type-check

# Lint
npm run lint
```

The app opens at [http://localhost:3000](http://localhost:3000).

## Features

### Chat interface
- Conversational interface for document processing and follow-up questions
- Session management: create, switch, and delete sessions (persisted in localStorage)
- PDF drag-and-drop: drag a PDF onto the chat area or the upload zone to auto-submit

### Document result view
- Structured display of extracted Ercole module requests
- Per-module: header name, assigned pages, extracted contact data, confidence score
- Expandable markdown summary generated by the AI pipeline
- Color-coded confidence indicators (green ≥ 85%, amber 70-84%, red < 70%)
- Warning section for unrecognized external modules

### API connectivity
- Live backend health indicator in the top bar (checks every 30 seconds)
- Configurable API URL via environment variable
- Error messages surface directly in the chat thread

## Architecture

```
app/
  layout.tsx          Root layout: Geist font, metadata
  page.tsx            Entry point (delegates to AppShell)
  globals.css         OKLCH color tokens, prose styles, scrollbar

components/
  AppShell.tsx        Session state, routing, API calls
  SessionSidebar.tsx  Session list with timestamps, create/delete
  ChatMain.tsx        Message list, input area, empty state
  DocumentResult.tsx  Structured result: stats, summary, module sections
  PdfDropzone.tsx     PDF drag-and-drop (full-size and compact)
  ui/
    button.tsx        Multi-variant button (primary, secondary, ghost)
    badge.tsx         Semantic badge (default, success, warning, error)
    separator.tsx     Horizontal/vertical divider
    skeleton.tsx      Loading placeholder with pulse animation
    textarea.tsx      Auto-resizing textarea with focus styling

lib/
  types.ts            TypeScript types mirroring the Python Pydantic schemas
  api.ts              Typed API client (sendChatMessage, sendFollowUp, checkHealth)
  utils.ts            Helpers: ID generation, date formatting, localStorage persistence
```

## Design System

The frontend uses an OKLCH color system defined as CSS custom properties in `globals.css`. No hardcoded hex colors in component files.

**Accent**: deep amber-ochre `oklch(42% 0.145 65)` — archival warmth, breaks the financial-blue reflex.

**Neutrals**: warm parchment tinted toward the brand amber `oklch(97.5% 0.008 70)`.

**Font**: Geist Sans (Vercel) — clean, technically precise, appropriate for a data-dense document tool.

Design decisions follow the [impeccable design system](../.claude/skills/impeccable/) documented in [`PRODUCT.md`](../PRODUCT.md) and [`DESIGN.md`](../DESIGN.md).

## Adding Features

### New API endpoint
1. Add the typed function in `lib/api.ts`
2. Add the response type in `lib/types.ts`
3. Call it from `AppShell.tsx` or a component

### New message type
1. Extend the `Message` interface in `lib/types.ts`
2. Add a renderer in `ChatMain.tsx` (see `AssistantMessage` for the pattern)

### New session action (e.g., export)
1. Add the handler in `AppShell.tsx`
2. Add the UI control in `SessionSidebar.tsx`
